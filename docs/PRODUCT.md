# Spin — 产品形态定稿

> 品牌名暂定 **Spin**。代码内部标识符沿用代号 `sinew`（crate、C ABI 前缀 `sinew_`、TS 类名），品牌最终确定后一次性替换。

## 一句话

**从一张图到游戏里可交互的角色。**
面向独立团队的 2D 角色动画平台：AI 做体力活，人做表演；同一个内核同时跑在编辑器和所有引擎里。

## 北极星指标

**立绘 → 引擎里可玩角色 的时间。** 目标：30 分钟内出可用初版（Spine 手工流程通常以天计）。

## 目标用户

| 层级 | 用户 | 用途 |
|---|---|---|
| 核心 | 1–20 人独立团队（美术兼动画、程序兼 TA） | Godot / Unity / Web 游戏角色 |
| 扩展 | 中小商业团队 | 替换 Spine 的生产管线 |
| 外延 | UI/营销动效、VTuber、互动叙事、教育 | 交互动画、实时驱动 |

## 产品五层（终局形态）

### 1. Spin Core — 单一求值内核（Rust）

编辑器预览与游戏运行时是**同一份代码**，所见即所得由架构保证，而不是靠多语言移植对齐。

- 骨骼层级（5 种继承模式）、Slot、绘制顺序、Skin（含 skin 专属骨骼/约束）
- Attachment：Region、Mesh（加权）、Linked mesh、Clipping、BoundingBox、Point、Path、Sequence
- 约束：IK（1/2 骨、soft、stretch）、Transform（通用属性映射）、Path、Physics（弹簧/风/重力/碰撞）
- **通用属性通道动画**：任何属性都可 K 帧（骨骼、颜色、网格、约束参数、物理参数、材质参数、状态机输入）
- 动画混合：多轨道、crossfade、additive、hold、遮罩（按骨骼子树）
- **状态机**：状态、转换条件、Blend Tree（1D/2D）、层、输入参数、事件 —— 运行时零代码驱动
- **运行时注入**：外部输入驱动骨骼（注视目标、地面 IK、外力、受击方向），程序化与关键帧混合
- 渲染输出：双色 tint、PMA、混合模式、批次；后续 法线贴图 / 2D 光照 / 像素风旋转模式
- 编译目标：WASM + 原生（C ABI），一份实现覆盖全部平台

### 2. Spin Studio — 编辑器（Web 优先，Tauri 桌面版）

- **Rig 模式**：骨骼、Slot、Attachment、网格编辑、自动三角化、自动权重 + 权重笔刷、约束、Skin
- **Animate 模式**：Dopesheet、曲线编辑器（每通道独立）、Ghosting/洋葱皮、自动 K 帧、音频轨
- **Logic 模式**：状态机图编辑、Blend Tree、输入参数面板、实时试玩（键盘/手柄驱动预览）
- **协作**：实时多人编辑（CRDT 文档）、版本历史、分支/合并、逐帧评论、分享链接预览
- 导入：PSD（沿用 Spine 图层标签约定）、Aseprite、Spine JSON/skel、DragonBones（后期）
- 导出：Spin 运行时格式、Spine JSON（子集，保证可回退）、PNG 序列 / GIF / 视频、Sprite Sheet
- CLI：批量导出、CI 集成

### 3. Spin AI — 生产加速（每一步产出普通可编辑数据）

| 能力 | 输入 → 输出 |
|---|---|
| **图 → 角色** | 立绘/PSD → 自动拆件 + 遮挡区补全 + 骨骼 + 网格 + 权重 |
| **动作库 + 重定向** | 标准骨架模板（人形/四足/自定义）→ 任意角色一键套用 idle/walk/run/jump/attack/hit/die |
| **视频 → 动作** | 参考视频 → 2D 姿态估计 → 关键帧（可编辑） |
| **文本 → 动作** | "受伤后踉跄后退" → LLM 规划 + 动作原语组合 → 关键帧 |
| **二级动作** | 自动生成头发/衣物/尾巴的跟随与物理参数 |
| **中间帧** | 稀疏关键帧 → 补全 |

原则：AI 不产出视频、不产出黑盒，只产出 Studio 里可继续编辑的骨骼、网格、关键帧。

### 4. Spin Runtimes — 全部 MIT

Web（TS + WASM）、Godot（GDExtension）、Unity（C# + native）、Unreal（C++ 插件）、Defold / Bevy / 原生 C。
运行时不绑定编辑器授权 —— 这是对 Spine 最直接的结构性差异。

### 5. Spin Hub — 云与市场

- 项目云存储、版本、团队权限
- **资产市场**：Rig 模板、动作包、角色、状态机模板（动作可跨角色复用后，市场才成立）
- 公开作品页（嵌入式播放器，可分享）

## 相对 Spine 的天花板决策

| 维度 | Spine | Spin | 天花板差异 |
|---|---|---|---|
| 求值内核 | Java 参考实现 + 每语言手写移植 | 单一 Rust 内核 + C ABI / WASM | 新功能一次实现、全平台同步；编辑器 = 运行时 |
| 动画通道 | 固定 timeline 类型 | 通用属性通道 | 任何新属性天然可动画 |
| 交互逻辑 | 无，需在引擎里写代码 | 编辑器内状态机 / Blend Tree | 美术独立交付可玩角色 |
| 动画复用 | 骨骼名必须一致 | 骨架模板 + 重定向 | 动作资产化 → 市场 |
| 文档模型 | 单机二进制工程文件 | CRDT 文档 | 实时协作、分支合并 |
| 生产方式 | 全手工 | AI 管线 + 手工精修 | 生产效率数量级差异 |
| 程序化 | Physics 约束 | Physics + 运行时注入 | 角色对游戏世界有反应 |
| 授权 | runtime 绑定编辑器授权 | runtime MIT | 采用门槛归零 |

## 兼容策略（让人敢换）

1. 导入 Spine 4.x JSON / skel 导出数据，老资产直接打开
2. 导出 Spine JSON 子集，随时可回退
3. PSD 图层标签、Setup/Animate 双模式、快捷键贴近 Spine 习惯

## 商业模式

| 层 | 定价 |
|---|---|
| Studio 个人版 + 全部 Runtime | 免费 |
| Team（协作、云版本、分支、权限） | 订阅，按席位 |
| AI | 按量计费 / 订阅含额度（有真实算力成本） |
| Hub 市场 | 交易抽成 |

## 边界（明确不做）

- 3D 骨骼动画
- 视频生成式"动画"（不可编辑的像素输出）
- 通用矢量设计工具（矢量 attachment 后期作为 attachment 类型加入，不做独立设计工具）

## 关键风险与验证顺序

1. **AI 图→角色质量**：决定差异化能否成立 → M3 前用 20 张不同画风角色做盲测
2. **Spine 数据兼容的视觉一致性** → 对照测试框架（用户本机官方 runtime 渲染比对）
3. **编辑器手感** → 早期招募 10–20 个独立团队持续试用
4. **引擎集成稳定性** → 每个引擎一套自动化示例工程回归
